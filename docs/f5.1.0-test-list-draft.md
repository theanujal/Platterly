## 0. How to read this document

### 0.1 Rules this list follows

- An expected result is stated only where an approved or relayed decision, or a clearly labelled inference (Derived), supports it. Nothing is presented as approved unless its source says so.
- Where behaviour is unresolved, the test is a scenario only. It is classed **Open** or **Blocked**, names the decision or prerequisite it needs, and states **no** expected result.
- Proposed text carried from Revision 5 is not approved. Tests that depend on it are **Open** and are classified by provenance in 18.8.2. Reg 2.4 records AJ's instruction to retain Revision 5's B1-B5 conditions as drafted, but records no separate approval of them; this list does not treat that instruction as approval.
- Related decisions do not resolve an open question. Examples: A1 and A2 do not close the plan's cooling-off question, and R-C1 to R-C4 do not close the invitee refusal-message question.
- Owner wording is preserved where Decision M is unresolved. No test treats the plan's central Owner as the Business Admin.
- Normal flows (O2, O3, O4) are kept apart from recovery claims. Recovery claims are tested in sections 3 and 7.
- The tests assume no database schema, API, user interface, service design or implementation detail. Where an expected result depends on one, the status is **Needs design**.

### 0.2 Fields

Each test has: ID, area, name, purpose, preconditions, steps, expected result, source reference, evidence classification and status. The Area column repeats the section heading in short form, and the ID prefix also identifies the area.

### 0.3 Evidence classification

| Class | Meaning here |
|---|---|
| A-H | Approved handover decision (2026-11-04), recorded in a project record (Gate B-1, W1 baseline decisions, Revision 5 sections 0A and 0E, the F5 handover). Same as Revision 6 `[A-H]` |
| A-R | Approved decision recorded in the decision register, relayed with full wording on 2026-11-05. Same as Revision 6 `[A-R]` |
| A-R+O | Relayed decision or clarification; original wording and date unavailable. Not direct approval. Same as Revision 6 `[A-R+O]` |
| Derived | An explicitly identified inference from approved source material. Not an approval |
| Historical | Retained Foundation Plan or Revision 5 wording that Revision 6 carries as a check but that is not a register decision. It must not automatically be treated as current policy, and it is subject to the C15 plan reconciliation |
| Open | Expected behaviour is not decided. The test is a scenario only |
| Blocked | Cannot be completed until a named decision or prerequisite is resolved |

**Mixed rows.** Where one row combines claims of different evidence classes, the Class cell gives the class of the primary assertion and each clause of the Expected result carries its own bracketed tag, for example [A-R, C14 pt 5], [Derived] or [Historical, Plan O2]. A bracketed [Derived] clause is an inference, not an approval, whatever the Class cell says.

### 0.4 Status

| Status | Meaning |
|---|---|
| Ready | The expected result is stated by the source (or labelled inference). The test can enter implementation planning. Ready does not mean implementation is authorised |
| Needs design | The expected result is stated, but its test depends on a technical design decision not yet made (Revision 6 section 10; C16 prerequisites 2 to 4), or the expected result itself waits on a design choice |
| Blocked | Waits on a named external prerequisite (D5, E2, F8, C7, C15) or on a named open decision (the TR-06 question) before it can be run. A Blocked row may state an expected result; a row of class Blocked has none |
| Open | Waits on an undecided policy question |
| Deferred | Deferred by AJ or by an approved implementation-time step |
